<objective>
Implementar un widget de entrada de texto (input) siempre visible junto al slider cuando `enable_keyboard_input = true`, permitiendo al usuario escribir valores numéricos directamente.

**Propósito:** Proveer entrada precisa de valores al estilo de ecualizadores profesionales (FabFilter Pro-Q, iZotope Ozone). El input se renderiza junto al slider con posición configurable, estilos personalizables, y validación de entrada. Enter o clic fuera confirma; valores inválidos se rechazan.

**Salida:** InputOverlay/widget de input integrado en CustomSlider, InputPosition/InputWidth enums, campos de estilo en Options, lógica de validación en update(), y conexión en audio_center.rs.
</objective>

  <action>
    **1. Agregar estado de edición del input a CustomSliderState:**
    ```
    is_input_editing: bool,
    input_value_text: String,
    input_has_focus: bool,
    ```

    **2. Implementar InputOverlay struct + Overlay impl:**
    El InputOverlay se renderiza como un widget iced separado (Element) pegado al slider según input_position.

    El InputOverlay recibe:
    - El valor actual del slider (formateado con format_fn si existe)
    - El estado de edición (is_input_editing, input_value_text)
    - input_position para saber dónde renderizar
    - input_gap, input_width, y todos los campos de estilo (input_bg_color, input_border_color, input_border_focus_color, input_border_width, input_border_radius, input_font_size, input_font_color)
    - slider_bounds (para posicionar relativo al slider)

    **Renderizado del input:**
    - Si input_width == Auto: calcular ancho basado en el contenido formateado + padding
    - Si input_width == Fixed(w): usar w como ancho
    - Alto: input_font_size + padding (proporcional al handle_size para consistencia)
    - Posición relativa al slider según input_position:
      - Right: a la derecha del slider, gap horizontal
      - Bottom: debajo del slider, gap vertical
      - Left: a la izquierda del slider, gap horizontal
      - Top: encima del slider, gap vertical
      - Auto: Right si orientación Horizontal, Bottom si orientación Vertical
    - Dibujar fondo (rounded rect con input_border_radius) en input_bg_color
    - Dibujar borde: usar input_border_color normalmente, input_border_focus_color solo si input_has_focus
    - Dibujar texto del valor (centrado vertical y horizontalmente, o alineado a la izquierda con padding)
    - Si is_input_editing: mostrar input_value_text con cursor parpadeante (| al final)

    **3. Agregar InputOverlay en CustomSlider::overlay():**
    Si `options.enable_keyboard_input == true`:
    - Si `state.is_input_editing` o siempre visible (según diseño: SIEMPRE visible), retornar Element del InputOverlay además del TooltipOverlay.

    En iced 0.14, `overlay()` retorna `Option<iced::advanced::overlay::Element>`. Se puede retornar solo un overlay. Si ya hay TooltipOverlay, habrá que elegir: ¿Tooltip e input pueden coexistir? Según el diseño, el input SIEMPRE es visible cuando enable_keyboard_input = true. El tooltip solo aparece en hover/drag. Si ambos deben mostrarse, se necesita un overlay combinado.

    **Estrategia:** Crear un overlay combinado que renderice tooltip (si aplica) e input (si enable_keyboard_input). Alternativamente, retornar solo el InputOverlay y que este también dibuje el tooltip.

    **Enfoque recomendado (simplicidad):**
    - Cuando enable_keyboard_input=true, el input overlay reemplaza la necesidad de tooltip (el valor siempre está visible).
    - InputOverlay::draw() renderiza el fondo, borde y texto del input.
    - Si además show_tooltip=true, el TooltipOverlay se renderiza ENCIMA (en overlay separado o combinado).
    - Para no complicar con overlays múltiples, se puede integrar: InputOverlay contiene la lógica de tooltip si show_tooltip=true y hay hover activo.

    **Alternativa más simple:** El InputOverlay se renderiza en `draw()` (no como overlay). Se dibuja directo en el renderer como parte del widget, usando fill_quad + fill_text. Esto evita la limitación de un solo overlay.

    **Decisión recomendada:** Renderizar input en `draw()` después de dibujar slider. Input no necesita ser overlay porque siempre está visible y no necesita Z-ordering especial (el tooltip sí por ir sobre otros widgets). El tooltip sigue siendo overlay.

    **4. Lógica de input en update():**
    Agregar manejadores de eventos para el input:
    
    - **Clic en el input** (Mouse ButtonPressed Left con cursor dentro del área del input): `state.is_input_editing = true`, `state.input_value_text = self.format_display_value(self.value)`, `state.input_has_focus = true`
    - **KeyPressed Enter** (cuando input_has_focus): Intentar parsear `state.input_value_text` como f32:
      - Éxito: si el valor está dentro del rango, `self.value = parsed.clamp(...)`, `shell.publish((self.on_change)(self.value))`, `state.is_input_editing = false`
      - Fracaso (no numérico o fuera de rango): `state.is_input_editing = false` (rechazar, mantener valor anterior)
    - **KeyPressed Escape** (cuando input_has_focus): `state.is_input_editing = false` (cancelar, mantener valor anterior)
    - **KeyPressed Character(c)** (cuando input_has_focus y is_input_editing):
      - Si `c` es un carácter de texto válido (dígitos, punto, guión): agregar a `state.input_value_text`
      - Si `c == '\u{8}'` (backspace): eliminar último carácter
    - **Clic fuera del input** (Mouse ButtonPressed Left con cursor fuera del input, cuando input_has_focus): Misma lógica que Enter (confirmar si válido, rechazar si no)

    **5. Formato inicial del input:**
    Cuando `is_input_editing` se activa, el texto inicial debe ser el valor actual formateado. Usar `self.format_display_value(self.value)` que respeta `format_fn`.

    **6. Colores y estilos en draw():**
    En el renderizado del input en draw():
    - Usar `input_bg_color.unwrap_or(COLOR_BG)` para el fondo
    - Usar `input_border_color.unwrap_or(COLOR_TEXT_SECONDARY)` para el borde normal
    - Usar `input_border_focus_color.unwrap_or(COLOR_ACCENT)` cuando `input_has_focus`
    - Usar `input_border_width` y `input_border_radius` para el borde
    - Usar `input_font_size` para el texto
    - Usar `input_font_color.unwrap_or(COLOR_TEXT_PRIMARY)` para el color del texto
    - Fuente: FONT_INTER_SANS_MEDIUM
    - Alineación del texto: centrado vertical, padding horizontal de 6px
