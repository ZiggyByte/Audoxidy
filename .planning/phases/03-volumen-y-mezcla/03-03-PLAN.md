**Fade coefficient computation (per-batch):**

```
let fade_coeff = match &mut fade_state {
    FadeState::Idle => 1.0,
    FadeState::FadingIn { coeff, step_per_frame } => {
        if *coeff >= 1.0 {
            *fade_state = FadeState::Idle;
            1.0
        } else {
            let current = *coeff;
            // Equal-power fade-in (D-12): sin²(π/2 * t) where t=coeff
            let ep_coeff = (std::f64::consts::PI / 2.0 * current).sin().powi(2);
            *coeff += *step_per_frame;
            if *coeff > 1.0 { *coeff = 1.0; }
            ep_coeff
        }
    }
    FadeState::FadingOut { coeff, step_per_frame } => {
        if *coeff <= 0.0 {
            *fade_state = FadeState::Idle;
            0.0 // Complete silence at fade end
        } else {
            let current = *coeff;
            let ep_coeff = (std::f64::consts::PI / 2.0 * current).sin().powi(2);
            *coeff -= *step_per_frame;
            if *coeff < 0.0 { *coeff = 0.0; }
            ep_coeff
        }
    }
    FadeState::Smoothing { coeff, target, step_per_frame } => {
        // Linear ramp for 500ms volume smoothing (D-08)
        if (*coeff - *target).abs() < *step_per_frame {
            *coeff = *target;
            *fade_state = FadeState::Idle;
            *target
        } else if *coeff < *target {
            *coeff += *step_per_frame;
            *coeff
        } else {
            *coeff -= *step_per_frame;
            *coeff
        }
    }
};
```

**Part B — RMS measurement per-batch**

Insert BEFORE the gain computation (Task 1's block, before `let s = state.read();`). Measure on `output_accumulator` (post-gain from previous iteration, or pre-gain for the current batch — use the current batch, measured after the downmix/resample but before gain application, to avoid feedback loop):

Actually, per D-21: RMS is measured POST-RG (after gain application) — so the normalization loop sees the signal with RG already applied. This means normalizing makes RG'd tracks level-matched regardless of their original loudness.

The measurement placement: **after** the `gain_linear` multiplication in the DSP loop of the PREVIOUS batch, but recorded before processing this batch. Since we can't look ahead, use the current `output_accumulator` BEFORE applying gain to it (this batch will have gain applied to the NEXT RMS reading). This introduces ~1 batch of latency (~2ms at 44.1kHz) which is negligible.

Implementation: compute RMS on `output_accumulator` at the start of the processing block, before gain application:

```rust
// RMS Normalization measurement (D-21: ~400ms window, post-RG measurement)
// Measure the batch BEFORE gain so this measurement feeds next iteration's gain.
if s.normalize_enabled {
    // Per-frame RMS² accumulation
    for frame in output_accumulator.chunks(out_channels as usize) {
        let frame_power: f64 = frame.iter().map(|s| s * s).sum::<f64>() / out_channels as f64;
        if rms_window.len() >= rms_window.capacity() {
            if let Some(old) = rms_window.pop_front() {
                rms_sum_sq -= old;
            }
        }
        rms_window.push_back(frame_power);
        rms_sum_sq += frame_power;
    }
    let measured_rms = (rms_sum_sq / rms_window.len().max(1) as f64).sqrt().max(1e-10);
    let measured_db = 20.0 * measured_rms.log10();
    let target_db = s.normalize_target_db as f64;
    let error_db = target_db - measured_db;
    let cap_db = s.normalize_cap_db as f64;
    let target_gain_db = error_db.clamp(0.0, cap_db); // Only boost, never attenuate

    // Attack/Release smoothing (D-24)
    let dt = output_accumulator.len() as f64 / out_channels as f64 / out_rate as f64;
    let tc = if target_gain_db > normalization_gain_db { 3.0 } else { 1.0 };
    // Exponential moving average: 1 - exp(-dt/tc)
    let alpha = 1.0 - (-dt / tc).exp();
    normalization_gain_db += (target_gain_db - normalization_gain_db) * alpha;

    // NaN guard
    if !normalization_gain_db.is_finite() {
        normalization_gain_db = 0.0;
    }
}
```

**Part D — Fix B1 (D-44): DSP spin-wait**

Replace the `try_write()` at line 820 with a spin-wait loop:

```rust
// Fix B1 (D-44): Spin-wait for DSP lock up to 5ms before falling back.
// This prevents DSP dropout during brief GUI lock contention.
use std::time::Instant;
let dsp_lock = {
    let deadline = Instant::now() + std::time::Duration::from_millis(5);
    loop {
        if let Some(lock) = engine.dsp.try_write() {
            break Some(lock);
        }
        if Instant::now() >= deadline {
            break None;
        }
        std::hint::spin_loop();
    }
};

if let Some(mut dsp_lock) = dsp_lock {
    // Process with DSP: gain → DspChain → fades×volume
    // (reordered from old code per D-03)
    for frame in output_accumulator.chunks_mut(out_ch) {
        for s in frame.iter_mut() { *s *= gain_linear; }
        dsp_lock.process_frame(frame);
        // fade_coeff * vol applied here
        let combined = vol * fade_coeff; // from Task 2
        for s in frame.iter_mut() { *s *= combined; }
    }
} else {
    // Fallback (rare: GUI held lock >5ms): apply gain×volume WITHOUT DSP
    tracing::debug!("DSP lock timeout: applying gain×volume without effects to maintain playback.");
    let combined = gain_linear * vol * fade_coeff;
    for frame in output_accumulator.chunks_mut(out_ch) {
        for s in frame.iter_mut() { *s *= combined; }
    }
}
```

**IMPORTANT:** The fallback (DSP skipped) still applies `fade_coeff` for smooth audio. Without DSP processing, listeners lose effects but not volume/fade continuity. This is acceptable for the <0.1% of cases where the lock contention exceeds 5ms.
